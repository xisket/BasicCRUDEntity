# Employee CRUD API

[English](README.md) | [Español](README.es.md)

A REST API for managing employees, built with .NET 10, ASP.NET Core Controllers, Entity Framework Core, and SQLite.

## Features

- Create, retrieve, update, and delete employees.
- Employee fields: ID, name, email, and department.
- Input validation and unique email addresses.
- Paginated employee listing.
- Structured error responses using Problem Details.
- Swagger UI and OpenAPI documentation in Development.
- Integration tests covering CRUD operations, validation, duplicate emails, missing records, pagination, and API documentation.

## Project structure

- `src/EmployeeCrud.Api`: API configuration, employee endpoints, request/response DTOs, and database context.
- `tests/EmployeeCrud.Tests`: HTTP integration tests using an isolated SQLite database for each test.

## Getting started

Requires the .NET 10 SDK. Run these commands from the repository root:

```powershell
dotnet restore
dotnet test
dotnet run --project src/EmployeeCrud.Api
```

The default HTTP launch profile runs the API at `http://localhost:5050` in Development. IDEs that support the launch profile open Swagger automatically. When using `dotnet run`, open [Swagger UI](http://localhost:5050/swagger) manually.

The [OpenAPI document](http://localhost:5050/openapi/v1.json) and Swagger UI are available only in Development. Sample requests are also provided in `src/EmployeeCrud.Api/EmployeeCrud.Api.http`.

## Database

SQLite stores data in `src/EmployeeCrud.Api/employees.db` by default. The database is created automatically on startup, and data persists across restarts. No separate database server or Docker installation is required.

Set `ConnectionStrings:Employees` in configuration to override the connection string, or use the `ConnectionStrings__Employees` environment variable.

Schema initialization uses `EnsureCreatedAsync`; it does not apply schema changes to an existing database. To reset local data, stop the API and remove the database file and any associated `-wal` and `-shm` files.

## Endpoints

| Operation | Endpoint | Responses |
| --- | --- | --- |
| Create | POST `/api/employees` | 201 with response body and Location header; 400 or 409 |
| List | GET `/api/employees?page=1&pageSize=20` | 200 with items, page, pageSize, and total; 400 |
| Retrieve | GET `/api/employees/{id}` | 200 or 404 |
| Replace editable fields | PUT `/api/employees/{id}` | 204, 400, 404, or 409 |
| Delete | DELETE `/api/employees/{id}` | 204 or 404 |

Names and departments are required and limited to 100 characters. Emails are required, validated, limited to 254 characters, trimmed, and stored in lowercase. A unique database index prevents duplicate email addresses. Employee IDs are generated by the database. Page size ranges from 1 to 100 and defaults to 20.

### Example

```powershell
Invoke-RestMethod http://localhost:5050/api/employees -Method Post -ContentType 'application/json' -Body '{"name":"Ana Perez","email":"ana@example.com","department":"HR"}'
Invoke-RestMethod http://localhost:5050/api/employees
```
